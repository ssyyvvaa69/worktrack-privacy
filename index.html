WorkTrack Privacy Policy

Last updated: September 14, 2026

Developer: Miia Forge
Privacy contact: miiaforge.dev@gmail.com

1. General information

This policy describes WorkTrack 1.0, an Android application for personal tracking of working time, earnings and vacation. WorkTrack does not require registration or a user account and primarily stores user data locally on the device. This does not mean that no information ever leaves the device: official holiday requests, Android system backup and user-initiated file transfers are explained below.

The Privacy Policy accessible inside the application is an offline document; opening that document does not itself make a network request. Accessing a published web copy requires a connection to its hosting service.

2. Data used by WorkTrack

WorkTrack uses work dates and hours, hourly rates, segments and multipliers, vacation entries, goals, notes and custom holidays entered by the user. It calculates earnings and statistics from these records. It also uses application settings, including language, interface, currency, holiday calendar and user-selected background images. These data support the application's functions, not advertising profiling.

WorkTrack does not request GPS or location permissions. Initial region-related choices use the system locale and application settings, not GPS. The selected holiday country is a calendar setting and is not a measurement of the user's physical location.

3. Local storage and Android system backup

Work records, goals and custom holidays are stored in an internal database. Settings and processed background images are stored in application storage. WorkTrack does not send work records, rates, earnings, notes, custom holidays or photographs to a developer server.

Local data remains until deleted by the user, replaced during restoration or removed by clearing application data. Android system backup is enabled (android:allowBackup=true). Depending on the device, account and system settings, Android may automatically back up or transfer eligible application data, including records and settings. This is a separate operating-system mechanism, not an upload to a WorkTrack server. Device and account settings control it.

Processed background images are stored in Android's no-backup directory, but may be included in a manual WorkTrack backup. Deleting local data does not delete previously created external backups or exports.

4. Manual backup, export, sharing and restoration

The user initiates manual backups, exports and sharing. Backups may include work records, notes, custom holidays, goals, settings and selected background images. CSV and XLSX exports contain records and calculated information for the selected scope, including notes.

Android's document picker/CreateDocument and Sharesheet let the user choose a storage destination or receiving application, which may be a third-party or cloud service such as Google Drive. WorkTrack does not independently upload these archives to a server. A chosen service may transfer the file under its own terms and privacy practices.

Backup, CSV and XLSX files may contain personal and financial information and are not additionally encrypted by WorkTrack. After transfer, WorkTrack does not control the receiving service's storage, retention or deletion. Temporary files prepared for sharing may remain in the application cache.

Restoration is initiated by choosing a backup and confirming replacement of current data. If a cloud file provider is selected, that provider may download the chosen file. Keep backups safe and verify the selected file before restoring.

5. Selected files and background images

Photo Picker and file picker flows give WorkTrack access to the files selected by the user. WorkTrack does not request unrestricted access to the photo library or device storage.

When a background image is selected, WorkTrack stores a processed local copy for display. The image is not sent to the developer. It may be included in a manual backup that the user creates and shares.

6. Internet, official holidays and notifications

For official public holidays, WorkTrack uses the external Nager.Holidays HTTPS API at nagerholidays.com. Requests include the holiday country code, year and standard technical HTTPS request information. The external server technically receives the device's public-facing IP address. Work records, rates, earnings, notes, custom holiday titles and background images are not included in these requests.

The official holiday calendar is enabled by default. Requests may run automatically, including in the background for official holiday reminders. Results are cached locally. Users can disable the official holiday calendar in the application's holiday settings. Notification mode settings separately control reminders.

The provider's own rules govern its handling of technical request data. WorkTrack does not control or specify the provider's log-retention periods. This policy does not claim that the provider uses IP addresses for geolocation or identification; that use has not been established by the application audit.

Notifications are local reminders scheduled using Android WorkManager, not Firebase Cloud Messaging. On supported Android versions, notification permission is requested. Reminders may display holiday titles on the lock screen. Android may delay or block reminders; do not rely on them for essential obligations. Custom holidays and notes remain local unless included in backup or sharing as described above.

7. Advertising, analytics and third-party services

WorkTrack 1.0 contains no advertising. It does not use Firebase Analytics, Google Analytics, AdMob, Advertising ID, advertising SDKs, Crashlytics, Sentry or tracking SDKs. It does not use Firebase Cloud Messaging.

The external holiday API, Android system backup and user-selected sharing/storage services are distinct from advertising or analytics integrations. Their involvement is described in this policy.

Future versions may introduce services such as advertising. Before new processing is introduced, this policy must be updated to describe the service, data categories, purposes, recipients, retention and any required consent mechanism. Personalization controls and consent withdrawal must be described where applicable. This policy does not constitute consent to future processing.

8. Security, retention and control of data

WorkTrack uses Android internal application storage. Holiday API connections are protected by TLS/HTTPS. Exported files are not additionally encrypted by WorkTrack, and absolute security cannot be guaranteed. Protect your device and any backups or exports.

Records can be edited and deleted inside the application. All local application data can be cleared through Android settings. Copies held by external storage services or Android backup must be managed separately through the relevant service or device settings; WorkTrack does not remotely delete them.

Where data protection laws apply, rights may include access, correction, erasure, restriction, portability, objection and a complaint to a supervisory authority. For privacy questions, use the contact below. Because WorkTrack does not upload your work records to a developer server, the developer does not hold a server copy of those records to retrieve or delete.

9. Policy updates

This policy may be updated as the application changes. Privacy information is accessible inside the application under Settings → About → Privacy Policy. New processing and any required consent mechanisms must be described before that processing begins. The date above identifies this revision.
